Airport Investment Intelligence Agent

Run guide for first-time users: from a fresh clone to your first answer in about five minutes.

The agent answers analyst questions about where US airports need more terminal capacity. Claude chooses the tools and writes the explanation; every number comes from deterministic code over public BTS and FAA data, and a grounding check flags any figure in an answer that does not trace back to tool output.

1What you need

  • Node.js 22 or newer (check with node -v). The project runs TypeScript files directly, so there is no build step. If you are on an early 22.x release and see a "Unknown file extension .ts" error, update Node.
  • Git, to clone the repository.
  • An Anthropic API key for the real agent. Not needed for the demo in step 3.
  • No data download: the processed data ships with the repo (snapshot/*.parquet, about 22 MB). On first start the app builds its local database data/airports.duckdb from it automatically.

2Install

git clone https://github.com/Omrizz/airpoer-agent.git
cd airpoer-agent
npm install

3Try it without an API key (demo mode)

npm run web:demo

Open http://localhost:3000. A banner says DEMO MODE: answers are scripted from the real tools and real data, with no language model involved. Only the four example questions on the welcome screen work in this mode. It is the quickest way to see the UI, the tool trace and the score charts.

4Run the real agent

Create a .env file from the template and paste your key into it:

# macOS / Linux / Git Bash / PowerShell
cp .env.example .env
# Windows Command Prompt
copy .env.example .env

Edit .env so it reads ANTHROPIC_API_KEY=sk-ant-..., then start the web UI:

npm run web

Open http://localhost:3000 and ask a question. Each answer shows the tools the agent called, the data behind the numbers, and a note if any figure could not be traced to tool output. Stop the server with Ctrl+C.

If it does not start: ".env: not found" means the .env file is missing (step 4). A banner saying "Chat is disabled: no ANTHROPIC_API_KEY found" means the file exists but the key line is empty. Port 3000 busy? Set another one, for example PORT=3001 npm run web (PowerShell: $env:PORT=3001; npm run web).
Optional settings in .env: the default model is claude-sonnet-5-5. Set ANTHROPIC_MODEL=claude-opus-5-5 for the most thorough answers (about twice the cost), or ANTHROPIC_EFFORT=low|medium|high. See docs/MODEL_CHOICE.md.

5Questions to try

Which airports in New England are strong candidates for terminal expansion? (ranking with score breakdown; then try the follow-ups "Why is Portland ranked above Bangor?" and "What changes if we care much more about growth than congestion?")

Compare LA and Santa Ana airport congestion levels. (side-by-side delays and taxi times, LAX vs SNA)

What is the unmet flight demand in SFO airport and why? (demand-gap proxies, since unmet demand cannot be measured directly)

What is the percentage of long haul flights out of Anchorage airport? (route mix by distance)

What's an expansion at Newark worth? (dollar scenarios built on Newark's filed FY2025 revenue and costs; kept separate from the score, with every assumption stated)

How do you score airports? (the agent explains the 10 KPIs and four weighted components)

The first four also work in demo mode. The rest need the real agent.

7Where to read more

  • docs/DESIGN.md: design overview, how each exam requirement is met, KPI table.
  • docs/SCORING.md: KPI definitions, weights, percentile scoring and sensitivity.
  • docs/FINANCE.md: the dollar scenarios and their assumptions.
  • docs/TOOLS.md: the tools the agent can call. DATA_CHECK.md: data sources and checks.
Read before trusting a ranking: scores screen for demand pressure; they do not model construction cost, returns, or whether the terminal is the binding constraint. Congestion uses six alternating months of on-time data from large reporting carriers. "Unmet demand" is reported through proxies because it cannot be measured directly.
